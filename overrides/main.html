{# Material theme override: inject the PostHog analytics snippet into every page's . ``extrahead`` is the documented hook for this. Endpoint is the maintainer's reverse proxy at ``t.dmello.io``, not ``us.i.posthog.com`` directly. The proxy forwards both ``/i/v0/e/`` (events) and ``/static/array.js`` (the lazy-loaded SDK bundle) to the real PostHog hosts. Going via a first-party-looking domain sidesteps ad-blockers that silently drop requests to known analytics origins (uBlock's default lists, Pi-hole, NextDNS); the events PostHog ultimately receives are byte-identical. ``ui_host`` points at the real PostHog so the "view in PostHog" deep-links the SDK occasionally renders resolve correctly. Without it the SDK would try to link back to ``t.dmello.io/insights/...`` which doesn't exist. Privacy configuration: * ``person_profiles: 'identified_only'`` — no person profile is created for anonymous docs visitors. We never call identify(), so no profile is ever created. * ``disable_session_recording: true`` — no session replay. * ``autocapture: false`` — no automatic click / form / scroll tracking. The snippet captures exactly two things: the page view events below (URL, referrer, basic browser info) and ``store_outbound_click`` for clicks on links to device-vendor stores (destination URL + link text only), so the store demand the docs generate — affiliate-tagged links included — is counted alongside tesserae.ink's. * ``respect_dnt: true`` — honour Do-Not-Track headers. * ``capture_pageview: false`` — we fire ``$pageview`` ourselves via the ``document$`` subscription below. Material's ``navigation.instant`` feature swaps the DOM in place on link clicks without re-running the head snippet, so PostHog's built-in auto-capture only sees the FIRST hard load (every subsequent page is invisible). Material exposes a global ``document$`` RxJS observable that fires on every navigation, including the initial load and every instant swap; subscribing to it and calling ``posthog.capture('$pageview', …)`` ourselves gives us one event per page with no duplicates and no misses. * ``persistence: 'memory'`` — no cookies, no localStorage. The ``distinct_id`` lives only in the page's JS heap, so it resets on every navigation. Unique-visitor counts inflate as a result, but the metrics this snippet actually cares about (pageviews, country, referrer, time-of-day) all still work and no GDPR / ePrivacy consent banner is required because no persistent identifier is written to the browser. Closed over by ``cross_subdomain_cookie: false`` below as belt-and-braces. * ``cross_subdomain_cookie: false`` — defensive; with memory persistence there's no cookie to span subdomains anyway. Pre-v0.64 this slot held a Umami snippet pointing at ``analytics.dmello.io``. PostHog is now the docs-site analytics backend.
