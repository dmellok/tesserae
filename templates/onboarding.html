Welcome to Tesserae

A few quick steps to get a dashboard onto your first panel. You can skip any time and configure things later under Settings.

  1. Timezone, so schedules fire at your wall-clock time.
  2. Transport, REST API (no broker needed) or MQTT.
  3. Device, pair the panel with a 6-digit code (REST) or register it via discovery (MQTT).
  4. Dashboard, a starter layout, pushed to the panel.

Help me build Tesserae

Tesserae is a solo project. If you opt in to anonymous usage stats, I get a real picture of how many people are running it and what versions they're on, which helps me decide what to prioritise and when it's safe to break old behaviour. It's a small honest signal, not a vanity dashboard.

What gets sent (only when ticked):

  • app.started, once per process start, with the Tesserae version, Python version, and platform name.
  • app.heartbeat, once an hour while the process is running, so I can tell live installs apart from "started once and crashed". Same fields as above.
  • update.applied, when the in-app updater applies a new revision, with the from/to short SHAs, channel, and whether deps were reinstalled.

What it doesn't send: IP addresses, hostnames, paths, settings, secrets, push contents, dashboard layouts, or anything tied to a real-world identity. The only stable identifier is a random UUID generated on this install and stored in data/core/.instance_id.

Events go to my PostHog Cloud project, configured to disable IP storage, person profiles, and session recording. Country and region are recorded so I can see roughly where Tesserae's running. More detail in the privacy doc.
